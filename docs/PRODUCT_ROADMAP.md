# LingoFlow 产品完善与版本演进路线图

> **规划日期**：2026 年 9 月 15 日  
> **规划视角**：资深产品经理 / 核心体验官  
> **当前定位**：面向个人英语学习者的本地优先 PWA，把“口语表达、外刊精读、生词记忆”连接成一个学习闭环  
> **适用仓库**：`D:\d\lingoflow`  
> **路线图文档**：`docs/PRODUCT_ROADMAP.md`

---

## 一、结论摘要

LingoFlow 已经不是一个只有界面的演示原型。当前版本已经具备四条真实可用的能力：

1. **口语对练**：支持多场景对话、文字或语音输入、AI 纠错、自然朗读、生词通缉和历史对话延续。
2. **精读伴读**：支持内置文章、网页提取、AI 生成新文章、点词查询、长难句解析、段落翻译、阅读位置恢复、划线批注和 Markdown 笔记导出。
3. **生词复习**：支持生词收藏、随机闪卡、分级复习、掌握状态、AI 测验、错题回炉、生词微剧场和已牢记词查看。
4. **个人配置**：支持自备 AI Key、多家兼容服务、语音偏好、PWA 安装以及 JSON 数据导入导出。

因此，新路线图不应继续无节制地堆叠“看起来很酷”的功能，而应按以下顺序演进：

> **先补信任与可靠性 → 再建立每天打开的学习节奏 → 最后发展真正难以替代的个性化能力。**

### 建议版本节奏

| 阶段 | 建议版本 | 核心目标 | 用户得到的直接价值 |
|---|---|---|---|
| **P0：紧急填坑** | **v1.6「安心使用」** | 数据不丢、密钥不外泄、失败可恢复、弱网仍能打开 | “我敢长期把学习记录放在这里” |
| **P1：体验飞跃** | **v1.8「每日学习」** | 每天打开后立刻知道学什么，并能看到真实进步 | “它替我安排好了今天的 10 分钟” |
| **P2：亮点进阶** | **v2.0「个人语言教练」** | 从通用 AI 工具升级为理解个人薄弱点的长期教练 | “它越来越懂我，而且别的软件替代不了” |

## 二、规划依据：当前产品的真实基线

### 2.1 已经稳定存在的能力

| 用户任务 | 当前可完成程度 | 事实依据 |
|---|---:|---|
| 与 AI 外教进行连续口语对话 | 已可完成 | `src/components/OralCoach.jsx` 使用场景历史、流式回复、纠错和朗读；`src/services/ai.js:309-402` 处理近期对话与更早记忆片段 |
| 从阅读中收藏生词并复习 | 已形成闭环 | `src/components/SmartReader.jsx` 点词收藏；`src/components/VocabularySRS.jsx` 闪卡、状态筛选和复习反馈 |
| 读新文章而不是固定样例 | 已可完成 | `src/components/SmartReader.jsx:223-273` 支持文库随机换篇和 AI 新文章生成 |
| 收藏句子和记录读书心得 | 已可完成 | `src/components/SmartReader.jsx:128-220` 保存划线批注并导出 Markdown |
| 查看已经牢记的词 | 已可完成 | `src/components/VocabularySRS.jsx:416-429` 顶部“牢记”直达；约第 730 行提供状态筛选 |
| 手工跨设备搬运词库和文章 | 部分完成 | `src/services/storage.js:342-421` 提供 JSON 导入导出与增量合并 |
| 完全断网后打开应用 | 未完成 | `public/sw.js` 当前只清理旧缓存并注销自己，不承担离线访问 |
| 自动跨端同步 | 未完成 | 当前没有账号、云端空间或 WebDAV 等同步入口 |
| 诊断具体音素与口音问题 | 未完成 | 当前语音入口负责把语音转成文字；AI 看到的是文字，不是原始录音 |

### 2.2 当前产品最值得保留的定位

路线图建议坚持以下四项原则：

- **本地优先**：生词、文章、对话和笔记默认留在用户自己的浏览器中。
- **自备 AI 服务**：继续允许用户选择自己的 AI 服务，不强迫绑定单一厂商。
- **闭环优先于功能数量**：新增能力必须至少连接“读、说、记、测”中的两个环节。
- **手机单手可用**：继续以 iPhone Safari/PWA 为第一体验基准，同时兼顾电脑浏览器。

### 2.3 本次规划的合理假设

1. 产品短期仍以个人自用或小范围用户为主，没有现成账号系统和后端服务。
2. 用户最重要的数据是个人生词进度、文章、批注、对话和学习记录。
3. AI 调用费用由用户自己的 Key 承担，因此所有 AI 功能都要提供清楚的等待、失败和重试反馈。
4. 本路线图只给出相对工作量和实施顺序，不承诺未经评估的具体日历工期。

# 三、P0 阶段：紧急填坑（v1.6「安心使用」）

## 阶段目标

当前产品已经“能学”，P0 的任务不是再增加内容，而是解决会动摇长期使用信心的问题：

- 备份必须完整；
- API Key 不能混在普通备份中传播；
- 网络或 AI 失败后不能让用户白做；
- 学习统计不能造成误解；
- 断网时至少能进入应用并使用本地内容。

## P0 优先级路线表

| 顺序 | 功能完善项 | 当前问题 | 用户价值 | 完成验收标准 | 相对工作量 |
|---:|---|---|---|---|---:|
| **P0-1** | **安全完整备份 2.0** | 当前备份只明确包含设置、生词和文章；没有包括对话、学习统计、阅读批注和阅读位置。与此同时，设置对象中包含 API Key，普通 JSON 备份会把它一并写入文件。 | 保护用户长期积累的数据，也避免用户把备份发到微信或网盘时顺带泄露密钥。 | ① 默认导出不包含 API Key；② 生词、文章、批注、对话、统计、阅读位置全部可备份；③ 导入前显示将新增/更新的数据数量；④ 导入错误文件不会覆盖现有数据；⑤ 提供一次完整的导出→清空测试环境→导入恢复验证。 | **小—中** |
| **P0-2** | **AI 失败后的“原地恢复”** | 口语、翻译、查词、文章生成和微剧场都依赖外部 AI；目前多处失败后主要弹出提示，缺少统一的一键重试。口语发送失败时，当前消息也没有形成可靠的持久记录。 | 弱网、余额不足或服务波动时，用户不必重新输入，学习流程不会突然断掉。 | ① 用户输入永不因请求失败消失；② 错误卡使用通俗语言区分“未配置、密钥无效、余额/限流、网络中断”；③ 每处失败都提供“重试”和“保留内容”；④ 重试不会重复加入生词或重复发送消息。 | **中** |
| **P0-3** | **真实可信的学习统计** | 当前连续天数默认从 1 天开始，而且主要由闪卡复习触发；阅读、批注和口语练习没有统一计入。用户可能看到“连续 1 天”，但实际上当天尚未完成任何学习。 | 数据与真实行为一致，建立对产品的信任。 | ① 未学习时显示 0 天；② 明确什么行为算一次有效学习；③ 口语、阅读、批注、复习均能贡献当日学习记录；④ 跨天、断签和补签规则写清楚；⑤ 统计页可解释数据来源。 | **中** |
| **P0-4** | **最小离线可用能力** | 当前 `public/sw.js` 会删除旧缓存并注销自身；完全断网时无法保证进入应用。 | 地铁、高铁、飞行模式下仍可打开已保存文章、查看笔记和复习本地生词。 | ① 断网重新打开仍能进入；② 已保存文章、生词、批注和闪卡可用；③ AI 功能明确显示“联网后可用”，而不是无限加载；④ 新版本上线后提示刷新，不让旧缓存长期卡住。 | **中** |
| **P0-5** | **危险操作保护与数据范围说明** | “重置演示数据”会覆盖生词和文章，但用户可能误以为会重置所有内容；删除文章后，与它关联的阅读位置和批注如何处理也没有统一说明。 | 用户能明确知道会失去什么，减少误删和残留数据。 | ① 重置前列出影响范围；② 要求二次确认；③ 提供“先备份再重置”；④ 删除文章时明确是否同时删除批注；⑤ 删除后不留下无法访问的孤立笔记。 | **小** |

## P0 版本出口条件

只有同时满足以下条件，v1.6 才算真正完成：

- 用户可以放心备份并恢复全部学习数据；
- 默认备份文件中找不到 API Key；
- 任意一次 AI 调用失败，都不会导致输入内容或学习记录丢失；
- 学习统计与实际行为一致；
- 断网时能打开应用，并使用已保存的非 AI 内容。

# 四、P1 阶段：体验飞跃（v1.8「每日学习」）

## 阶段目标

P1 要解决的不是“功能够不够多”，而是用户每天打开后的三个问题：

1. **我今天该学什么？**
2. **只花 10 分钟能不能完成？**
3. **我这周到底有没有进步？**

当前首页直接进入口语模块，虽然功能丰富，但缺少一个统领读、说、记、测的“今日学习入口”。因此 P1 应围绕日常节奏，而不是继续增加孤立页面。

## P1 优先级路线表

| 顺序 | 核心功能 | 建议体验 | 用户价值 | 完成验收标准 | 相对工作量 |
|---:|---|---|---|---|---:|
| **P1-1** | **今日 10 分钟学习台** | 打开应用先看到一张简洁任务卡：复习到期词、精读一小段、完成 3 轮口语、生词小测。允许选择 5/10/20 分钟。 | 消除“功能很多但不知道先点什么”的选择负担，形成每天打开的理由。 | ① 根据到期词和未完成内容自动组装任务；② 每完成一步即时更新进度；③ 中途退出可继续；④ 当天完成后显示清爽结算，不继续强塞任务。 | **中** |
| **P1-2** | **多题型记忆训练** | 在现有选择题之外增加听音辨义、看中文拼英文、例句填空、易混词对比。题型根据薄弱点自动调整。 | 从“认得”推进到“能拼、能听、能用”。 | ① 至少增加拼写和听音两类；② 错题自动进入近期复习；③ 同一词不会连续重复同一种题型；④ 用户可关闭不喜欢的题型。 | **中** |
| **P1-3** | **影子跟读基础版** | 用户听一句原声后录下自己的版本，可立即回放，并在同一页面切换“原声/我的声音”；先做自我对照，不急于承诺精确打分。 | 让口语练习从“说给机器转写”升级为“真正听见自己的发音”。 | ① 支持录制、回放、重录；② 原声和用户录音可快速对比；③ 录音默认只留本地；④ 用户可一键删除。 | **中** |
| **P1-4** | **周报与可解释成长轨迹** | 每周展示学习天数、口语轮数、阅读篇数、复习词数、从“学习中”进入“已牢记”的词，以及最常犯的表达问题。 | 用户能看到努力如何转化成成果，增强持续动力。 | ① 所有数字可追溯到具体记录；② 不用空洞的总分掩盖细节；③ 支持回看上周；④ 给出下周一条可执行建议。 | **中—大** |
| **P1-5** | **个性化难度与目标设置** | 用户选择目标（旅行、职场、雅思、日常表达）和当前程度；文章、情景和测验围绕目标调整。 | 减少内容过难或过浅，让每次学习更贴近真实需求。 | ① 首次可跳过；② 随时修改目标；③ 推荐内容说明“为什么适合你”；④ 用户能手动换掉不喜欢的推荐。 | **中** |
| **P1-6** | **温和提醒与连续学习保护** | 由用户主动选择提醒时间；错过一天时不进行羞辱式提醒，提供“3 分钟轻量补课”。 | 帮助形成习惯，同时避免打卡焦虑。 | ① 默认不开启；② 用户可选择频率；③ 支持暂停；④ 连续记录规则透明；⑤ 无通知能力时提供日历订阅或应用内提醒替代。 | **中** |

## P1 建议的每日闭环

```text
打开应用
  ↓
看到“今天 10 分钟”
  ↓
复习 5 个到期词（记）
  ↓
精读 1 段并收藏 1 句（读）
  ↓
用其中 2 个生词完成 3 轮对话（说）
  ↓
做 3 道小测（测）
  ↓
生成今日结算：学了什么、哪里进步、明天何时再见
```

这条链路比单纯增加“排行榜、积分商城、更多 AI 按钮”更符合当前产品定位。

# 五、P2 阶段：亮点进阶（v2.0「个人语言教练」）

## 阶段目标

P2 的核心不是跟成熟产品逐项复制，而是发挥 LingoFlow 已经拥有的跨模块优势：同一个生词能在阅读中遇见、在闪卡中复习、在口语中使用、在故事中再次出现。

差异化应围绕“**一个词从看懂到真正会用的证据链**”展开。

## P2 创新路线表

| 顺序 | 差异化能力 | 核心创意 | 为什么比普通同类产品更亮眼 | 边界与前提 |
|---:|---|---|---|---|
| **P2-1** | **生词能力护照** | 每个词不再只有“学习中/已牢记”，而是展示四枚证据章：读到过、听懂过、拼对过、口语中主动用过。 | 大多数词典只记录“收藏”和“背过”；这里记录的是“真正能使用”的成长证据。 | 掌握规则必须公开，不应因一次偶然命中就直接判定精通。 |
| **P2-2** | **AI 主动召回导演** | 系统在未来几天的文章、口语情景和微剧场中，有节奏地安排用户薄弱词重现，但不生硬堆词。 | 把间隔记忆从闪卡扩展到真实语境，形成“全产品级记忆曲线”。 | 需要限制同一批词的曝光频率，避免内容变得刻意。 |
| **P2-3** | **发音诊疗室** | 从影子跟读基础版升级到单词、句子和连读层面的诊断：标记可能读错的部分，并给出口形或节奏建议。 | 让“口语纠错”同时覆盖用词、语法、发音和节奏。 | 必须使用真正能处理原始录音的评测能力；不能仅根据转写文字假装给发音分。 |
| **P2-4** | **个人错误博物馆** | 自动归纳用户反复出现的中式英语、时态、搭配和发音问题，生成可回看的“我的典型错误”卡片，并定期安排针对性复练。 | AI 不只是回答当下问题，而是长期记住“我总会错在哪里”。 | 应允许用户删除敏感对话或关闭长期归纳。 |
| **P2-5** | **我的生活英语剧本** | 用户输入下周真实任务，如面试、旅行、英文汇报；系统自动生成连续几天的阅读材料、生词包、口语模拟和最终彩排。 | 把英语学习直接绑定现实目标，形成具有明确终点的短期训练营。 | 需要控制任务规模，避免一次生成大量无人完成的内容。 |
| **P2-6** | **隐私优先的可选同步** | 提供 WebDAV 或端到端加密同步，用户可使用自己的云盘；仍保留完全本地模式。 | 与强制注册账号的商业产品形成差异，适合重视隐私和多设备自用的人群。 | 同步冲突、密钥保管和恢复机制必须先设计清楚。 |
| **P2-7** | **可分享的学习作品** | 将一周最喜欢的外刊摘录、生词微剧场、口语进步片段生成一张可分享的学习周刊；默认隐藏私密内容。 | 分享的不只是打卡数字，而是用户真实学到的内容和作品。 | 分享前必须逐项预览并允许隐藏内容。 |

# 六、关键方案对比与取舍

## 6.1 跨设备数据：先安全备份，再谈自动同步

| 方案 | 优点 | 缺点 | 建议阶段 |
|---|---|---|---|
| **完整安全 JSON 备份** | 成本低、无需账号、符合当前本地优先定位 | 仍需手动传文件 | **P0 立即做** |
| **用户自有 WebDAV** | 可自动同步，隐私控制较强 | 首次配置对普通用户略复杂 | **P2 可选增强** |
| **自建账号云同步** | 用户体验最无感 | 需要服务器、账号、安全维护和隐私责任 | 当前不建议优先 |

## 6.2 发音能力：先让用户听见自己，再提供专业评分

| 方案 | 用户价值 | 可信度风险 | 建议阶段 |
|---|---:|---:|---|
| **录音与原声交替回放** | 高 | 低，不假装评分 | **P1** |
| **整句流利度与停顿提示** | 很高 | 中，需要可靠录音分析 | P2 前半段 |
| **音素级百分制评分** | 很高 | 高，若能力不足容易给出假精确分数 | **P2，验证供应能力后再做** |

## 6.3 离线能力：本地学习可用，不伪装 AI 离线

| 离线范围 | 建议 | 原因 |
|---|---|---|
| 已保存文章、生词、批注、闪卡 | 必须支持 | 数据已经在本地，用户有合理预期 |
| 已有对话与笔记回看 | 应支持 | 不需要新的 AI 请求 |
| AI 查词、翻译、生成和口语回复 | 明确标注联网后可用 | 当前依赖外部 AI 服务，不能伪装成离线能力 |
| 离线请求排队后自动提交 | 暂不优先 | 容易在网络恢复后产生用户不知情的调用费用 |

# 七、落地推进建议：下一步先做哪个小功能？

## 第一推荐：**“安全完整备份 2.0”中的第一小步——备份范围清单 + API Key 默认脱敏**

这是当前最值得立刻开始的具体小功能。

### 为什么不是先做更炫的发音评分或首页？

| 候选小功能 | 用户价值 | 实施风险 | 是否保护已有成果 | 推荐结论 |
|---|---:|---:|---:|---|
| **备份范围补全 + 密钥脱敏** | 很高 | 低 | **是** | **第一优先** |
| 今日学习首页 | 很高 | 中 | 否 | 备份完成后进入 P1 |
| 影子跟读录音 | 高 | 中 | 否 | P1 第三项 |
| 音标级发音评分 | 高 | 高 | 否 | 不适合作为下一小步 |
| 自动云同步 | 很高 | 很高 | 是 | 先把本地备份规则做正确后再做 |

### 这个小功能的具体范围

1. 在导出前显示清单：生词多少个、文章多少篇、划线批注多少条、对话多少个场景、学习记录多少天。
2. 默认不导出 API Key，并明确显示“密钥不会进入备份文件”。
3. 把当前遗漏的批注、对话、学习统计和阅读位置加入备份。
4. 导入前先预览变化，不立即覆盖。
5. 导入成功后显示清楚：新增多少、更新多少、跳过多少。

### 最小验收路径

```text
准备一份包含生词、文章、批注、对话和学习记录的数据
  ↓
导出 JSON
  ↓
检查文件中不存在 API Key
  ↓
在空白测试浏览器中导入
  ↓
逐项确认生词进度、文章、批注、对话和统计全部恢复
```

完成这一项后，产品才真正具备承载数月乃至数年个人学习数据的基础信任。

# 九、每个版本都必须遵守的产品验收原则

1. **不丢内容**：用户输入、录音、批注和复习进度都要先保存，再进行外部请求。
2. **不制造假数据**：学习天数、掌握状态和发音评分必须有真实行为依据。
3. **不制造死胡同**：任何失败页面都必须告诉用户发生了什么、内容是否保留、下一步能做什么。
4. **不强迫注册**：在没有必要之前，继续保留无需账号的本地模式。
5. **不为了 AI 而 AI**：如果普通本地功能能完成，就不额外消耗用户的 AI 调用额度。
6. **不破坏手机体验**：新增功能必须在 iPhone 小屏、Safari 和添加到主屏幕模式下实际验收。
7. **每次只强化一个主闭环**：版本发布说明应能用一句话讲清楚用户得到的变化。

# 十、剩余风险

- 项目当前没有自动化测试脚本，`package.json` 只有开发、构建、规范检查和预览命令；重要业务闭环仍需要真实浏览器与手机人工回归。
- 当前 AI 功能依赖用户选择的第三方服务，不同服务对结构化回复和流式输出的支持程度可能不同。
- 网页文章提取依赖外部读取服务，受目标网站限制、网络状况和页面结构变化影响。
- 浏览器本地数据可能因清理网站数据、无痕模式或系统回收而消失，因此 P0-1 不应延后。
- 自动云同步和专业发音评分都会显著扩大隐私、安全、成本和维护责任，必须在方案确认后独立立项，不宜夹带在普通体验优化中。
